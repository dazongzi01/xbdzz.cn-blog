# 📎 内部文档交叉引用规范

## 问题背景

在写文档时，经常需要引用其他章节的内容。如何优雅地表达这个引用？

## 规范

### ❌ 不要这样写

```markdown
参考"03_服务购买和搭建"指南里的安全防护部分
参考"05_宝塔安装高手可忽略"
部署 PC 管理端（参考 "09_代码-管理端打包"）
```

**问题：**
- 包含了数字和完整标题，看起来冗长
- 在微信等平台上可能显示不一致
- 重复了信息

### ✅ 应该这样写

**只保留下划线后面的部分，并加上超链接：**

```markdown
参考[安全防护](/01_初步了解/03_服务购买和搭建#安全防护)部分
参考[宝塔安装高手可忽略](/01_初步了解/05_宝塔安装高手可忽略)
部署 PC 管理端（参考[管理端打包](/01_初步了解/09_代码-管理端打包)）
```

## 引用格式规则

### 1. 整章节引用

**格式：** `[章节名（下划线后部分）](链接)`

**例子：**
```markdown
详见[创建站点并配置](/01_初步了解/07_创建站点并配置)
```

### 2. 引用特定小节

**格式：** `[小节名](/路径#锚点)`

**例子：**
```markdown
详见[常见问题速查](/01_初步了解/06_服务器运行环境#⚠️-常见问题速查)
参考[防火墙配置](/01_初步了解/07_创建站点并配置#配置防火墙规则)
```

### 3. 句子中的自然引用

**格式：** 在需要引用的地方直接加链接

**例子：**
```markdown
如果还没装宝塔，参考[宝塔安装](/01_初步了解/05_宝塔安装高手可忽略)。
```

### 4. 列表形式的引用

**格式：** 使用 Markdown 列表，每个引用一行

**例子：**
```markdown
接下来的步骤：

1. [服务器运行环境](/01_初步了解/06_服务器运行环境) - 配置必要的运行环境
2. [创建站点并配置](/01_初步了解/07_创建站点并配置) - 设置网站和反向代理
3. [Java项目打包](/01_初步了解/08_代码-Java项目打包) - 打包和部署后端
```

## 链接组成说明

### 完整路径示例

```
[显示文本](/01_初步了解/07_创建站点并配置#小节标题)
         ↑                          ↑                    ↑
       链接文本              文件路径                  锚点（可选）
```

### 路径规则

- **目录**：使用中文目录名：`/01_初步了解/`
- **文件名**：去掉 `.md` 后缀
- **锚点**：markdown 标题的小写 slug，空格改为 `-`

### 锚点示例

| 标题 | 锚点 |
|------|------|
| `## 🎯 第一步：选择云服务商` | `#🎯-第一步选择云服务商` |
| `### 常见问题速查` | `#常见问题速查` |
| `### Q: 服务器连接不上？` | `#q-服务器连接不上` |

## 在文档末尾的"接下来的步骤"部分

使用列表格式，每行一个链接：

```markdown
## 🎉 接下来的步骤

1. [服务器运行环境](/01_初步了解/06_服务器运行环境) - 配置 Nginx、MySQL 等
2. [创建站点并配置](/01_初步了解/07_创建站点并配置) - 设置网站和反向代理
3. [Java项目打包](/01_初步了解/08_代码-Java项目打包) - 打包和部署后端
```

## 原则总结

| 要素 | 规则 |
|------|------|
| **显示文本** | 只用下划线后面的部分（不要数字） |
| **链接** | 使用完整的 VitePress 路径 |
| **锚点** | 用于链接到具体小节（可选） |
| **格式** | 尽量自然融入句子，避免生硬列表 |

## 示例对比

### ❌ 旧方式
```markdown
参考"08_代码-Java项目打包"指南
详细步骤参考：
- "09_代码-管理端打包"
- "10_代码H5打包"
```

### ✅ 新方式
```markdown
参考[Java项目打包](/01_初步了解/08_代码-Java项目打包)指南
详细步骤参考：
1. [管理端打包](/01_初步了解/09_代码-管理端打包)
2. [H5打包](/01_初步了解/10_代码H5打包)
```

## 好处

1. ✅ **简洁** - 文本更短，更容易读
2. ✅ **一致** - 所有引用使用统一格式
3. ✅ **可点击** - 用户可以直接点击跳转
4. ✅ **可维护** - 后续改文件名时更容易处理
5. ✅ **跨平台** - 在所有平台都能正确显示
