# 📚 大粽子

大粽子的文章写作系统 - 重点写好内容 + 专业排版 + 支持自动部署

---

## 🎯 项目目标

建立一套**多层级方案对比的写作系统**：
- **专业的文章内容** - 多方案对比、有数据支撑
- **高质量的排版和配图** - 清晰专业的呈现
- **自动化部署** - VitePress构建和发布

**大粽子的职责**：
- ✅ 写好文章内容（按照规范）
- ✅ 配好排版和配图（按照规范）
- ✅ 手动发布到各平台（大粽子完全控制）

## 💡 核心写作方式

### 什么是"多层级方案对比"？

不是讲一个技术，而是对比多个方案：

```
方案1：XXX
├─ 原理说明
├─ 代码示例
├─ 优缺点分析
└─ 适用场景

方案2：YYY
├─ 原理说明
├─ 代码示例
├─ 优缺点分析
└─ 适用场景

方案3：ZZZ
（同样结构）

对比评估
├─ 性能对比表（实测数据）
├─ 成本对比表（开发/维护成本）
└─ 易用性对比

场景决策
├─ 场景1 → 推荐方案1 的原因
├─ 场景2 → 推荐方案2 的原因
└─ 场景3 → 推荐方案3 的原因

快速决策矩阵
├─ 性能要求 → 对应方案
├─ 数据量级 → 对应方案
└─ 开发周期 → 对应方案
```

### 为什么这样写？

✅ **有数据支撑** - 实测性能、成本量化、学习曲线
✅ **有清晰建议** - 不同场景的推荐方案
✅ **易于传播** - 对比性内容价值高、易被分享
✅ **帮助读者决策** - 快速决策矩阵让读者能直接找答案

## 🔧 write.sh - HTML 转 Markdown 工具

### 📖 功能说明

`write.sh` 是一个文档处理脚本，主要用于：
- 将 HTML 文件转换为 Markdown 格式
- 自动处理和保存图片
- 生成符合项目规范的完整文档

### 🎯 使用方法

**基本语法：**
```bash
bash write.sh <article-name> [files...] [--dir <directory>]
```

**参数说明：**
- `<article-name>` - 文章名称（必需），如：`02_搭建准备`、`03_公众号配置`
- `[files...]` - HTML 文件路径（可选），支持多个文件
- `[--dir <directory>]` - 输出目录（可选），不指定则自动判断

### 📋 使用场景

#### 场景 1：仅生成文章框架
```bash
bash write.sh 02_搭建准备
```

## 🚀 编译和部署

这个项目包含完整的自动化部署解决方案，支持一键编译、打包和上传到服务器。

### 快速部署命令

```bash
# 1️⃣ 编译文档
./deploy.sh build

# 2️⃣ 编译并显示统计信息
./deploy.sh build --stats

# 3️⃣ 打包部署文件
./deploy.sh package

# 4️⃣ 编译 + 打包（推荐用于日常构建）
./deploy.sh all

# 5️⃣ 完整部署（编译 + 打包 + 上传到服务器）
./deploy.sh deploy user@example.com /var/www/html
```

### 部署流程

**场景 A：本地构建，手动上传**
```bash
# 编译和打包
./deploy.sh all

# 打包文件在：deploy/ 目录（vitepress-dist_*.tar.gz）
# 手动上传到服务器后解压即可
```

**场景 B：完全自动化部署**
```bash
# 一条命令搞定：编译 → 打包 → 上传
./deploy.sh deploy user@example.com /var/www/html
```

### 服务器部署步骤

假设已通过上述命令上传了部署包：

```bash
# 1. 登录服务器
ssh user@example.com

# 2. 进入目标目录
cd /var/www/html

# 3. 解压部署包
tar -xzf vitepress-dist_*.tar.gz

# 4. 移动文件到正确位置
mv dist/* .

# 5. 清理临时文件
rm -rf dist vitepress-dist_*.tar.gz
```
